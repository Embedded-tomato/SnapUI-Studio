# 槽位式 UI 编辑器 V1 设计方案

> 状态：草案 v1 · 待评审
> 目标读者：项目维护者
> 文档约定：`doc/` 目录放所有设计与计划文档，命名 `NNN-主题.md`

## 1. 设计哲学

SquareLine 功能全面但自由度过高，初学者面对空白画布和像素级拖拽无从下手。

本产品反其道而行：**以"牺牲可塑性换统一风格、易维护性"为前提**——

- 组件不能随意摆放，只能落入预设**槽位 (Slot)**，像积木一样搭
- 槽位由**屏幕模板 (Screen Template)** 定义，模板的视觉风格和布局由系统保证
- 初学者：拖 → 吸附 → 完成；高级用户：后续开放"屏幕编辑模式"自定义模板

参考先例：LVGL 官方的 **SquareLine "Unit" 简化模式**、Figma 的变体约束、低代码平台的容器组件。

## 2. 核心概念（三层分离）

```
┌─────────────────────────────────────────────────┐
│ 屏幕模板 Screen Template    ← UI 系统层（V1 内置）│
│   └─ 槽位 Slot：位置/流向/容量/允许组件            │
│        └─ 系统槽（滚动区/手势层）不对外暴露         │
│             └─ 用户槽：放入 UI 组件                │
│                  └─ 组件 Component ← 组件层（可扩展）│
└─────────────────────────────────────────────────┘
```

**UI 系统与 UI 组件严格分开：**

| 层 | 内容 | V1 是否可编辑 |
|---|---|---|
| UI 系统层 | 模板、槽位定义、吸附规则、手势导航、滚动行为 | ❌ 内置（P2 开放屏幕编辑模式） |
| 组件层 | 按钮、标签、设置行、照片格等积木 | ✅ 拖拽使用；新增组件=注册定义 |

槽位的滑动/滚动效果属于系统行为（如内容区上下滑动、手势切屏），
**不作为组件暴露给用户**，用户只看到"这个槽位能放什么"。

## 3. 槽位模型

每个槽位：

```jsonc
{
  "id": "bottombar",
  "name": "底部操作栏",
  "rect": [0, 436, 480, 44],        // 或相对描述，模板决定
  "flow": "row",                    // row | column | grid-wrap
  "gap": 12,
  "align": "space-evenly",
  "allows": ["bigbutton", "spacer"],// 允许的组件类型；空=全部
  "max": 4,                         // 容量上限；省略=不限
  "unique": false,                  // 同槽同类型只允许一个
  "system": false,                  // true = 系统槽，不在画布上高亮/不可见
  "scrollable": false               // 内容溢出时系统提供滚动
}
```

内置模板示例（相机，对齐现有 `gen_lvgl.py` 常量）：

| 槽位 | 位置 | 流向 | 容量 |
|---|---|---|---|
| `topbar` | 顶部 44px | row | ≤3（电量/时钟/标题） |
| `leftbar` | 左列 128px | column | 参数项，不限 |
| `center` | 中右剩余 | 覆盖层（取景框/九宫格） | unique 组件各一 |
| `bottombar` | 底部 64px | row | ≤4 大按钮 |
| `body` | 标题下内容区（子页面） | column/grid-wrap | 不限，可滚动（系统行为） |

## 4. 组件模型

```jsonc
{
  "type": "setting-switch",
  "name": "设置开关行",
  "icon": "🔘",
  "desc": "标签 + 开关，整行",
  "slots": ["body"],               // 可落入哪些槽位（跨模板通用名）
  "unique": false,
  "propsSchema": [
    { "key": "label", "label": "标题", "kind": "text" },
    { "key": "on",    "label": "默认开", "kind": "boolean" }
  ],
  "defaultProps": { "label": "开关", "on": true }
}
```

与 `editor/src/types/editor.ts` 的 `ComponentDef` 同构，向后兼容。

## 5. 交互流程（V1）

### 5.1 打开应用

```
启动 → 模板选择（V1 只有"相机模板"，略过）→ 空槽位画布 + 组件面板
```

### 5.2 拖放吸附（核心交互）

1. **拖动开始**：组件面板项 `dragstart` → 画布进入"槽位侦测模式"
2. **跟随幽灵**：半透明幽灵组件跟随鼠标
3. **槽位高亮**：仅**该组件允许落入**的槽位高亮（蓝框呼吸），其余槽位淡出；
   鼠标悬停的合法槽位显示插入位置预览（虚影占据实际槽位位置）
4. **落入**：
   - 合法 → 幽灵动画收缩到槽位位置（150ms），组件入列
   - 非法（悬停在槽位外或不允许的槽）→ 红色抖动 + 幽灵弹回组件面板
   - 容量已满 → 槽位红色提示"已满"，拒绝
   - `unique` 冲突 → 提示"将替换原有 XX"，确认后替换
5. **槽位内调整**：槽内组件可拖动排序（同槽 reorder），跨槽拖动 = 先删后插

### 5.3 单屏 / 总览

沿用现有工具栏：总览网格（多屏自动吸附排版已实现）⇄ 单屏编辑。

### 5.4 属性编辑

点击槽内组件 → 右侧属性面板（按 `propsSchema` 生成表单）→ 实时回显画布。

### 5.5 验证与预览

- **WASM 实时仿真**（已有）：真实 LVGL 内核跑布局结果，手势切屏可交互
- 组件渲染 = 槽位 flex 布局，所见即所得

## 6. 数据模型（工程文件）

与 `examples/camera-demo.json` 同构，直接可被 `tools/gen_lvgl.py` 消费：

```jsonc
{
  "format": "snapui@1",
  "screen": { "width": 480, "height": 480, "shape": "RECT", "template": "camera" },
  "nav": { "preview": { "left": "settings" } },   // 手势导航表（系统行为，V1 给默认值）
  "pages": {
    "preview": [ { "id": "c1", "type": "clock", "slot": "topbar", "props": {} } ]
  }
}
```

`template` 字段决定槽位布局；同一份 JSON 既能渲染画布、也能生成 C 代码、也能跑 WASM 仿真。

## 7. 技术方案

落地位置：**converter（桌面软件，主线程）**。React 版 editor/ 暂停投入。

| 模块 | 现状 | V1 动作 |
|---|---|---|
| 槽位/组件注册表 | editor/ 里有 TS 定义，converter 没有 | 新建 `converter/ui/registry.js`：模板+槽位+组件统一定义（单一事实源） |
| 画布拖拽 | 无（spj 模式是纯预览） | 新建槽位模式画布：拖放/高亮/幽灵/拒绝动画 |
| 代码生成 | `tools/gen_lvgl.py` 已按槽位 flex 生成 | 只改接口对齐 registry 命名，逻辑不动 |
| WASM 仿真 | 已有，链路完整 | 直接复用 |
| 中文字体 | `gen_lvgl.py` 引用 `ui_font_chinese` 但字体文件缺失 | **必须解决**：用 lv_font_conv 生成子集字体的 .c 一并编译（见 8.2） |
| spj 导入 | 已有 | 保留为"导入模式"，与"新建模式"并列，互不干扰 |

`registry.js` 同时服务：组件面板（图标/名称）、画布（吸附规则）、
属性面板（schema 表单）、代码生成（槽位映射），一处定义四处生效。

## 8. V1 范围

### 8.1 做（In Scope）

- [ ] `registry.js`：相机模板 + 槽位定义 + 首批 12 个组件（标题/时钟/电量/参数/大按钮/设置开关行/设置滑块行/设置选项行/照片格/九宫格/直方图/进度行）
- [ ] 槽位模式画布：拖放吸附完整交互（高亮/幽灵/拒绝/排序/替换）
- [ ] 属性面板（schema 驱动）
- [ ] 页面管理：增删屏、改屏名、手势导航默认值
- [ ] 工程保存/加载 `.snapui.json`（本地文件）
- [ ] WASM 仿真 + 导出 C 工程（复用现有链路）
- [ ] 总览/单屏切换接入新画布

### 8.2 关键风险

| 风险 | 应对 |
|---|---|
| 中文字体缺失导致仿真/导出代码编译失败 | 引入 lv_font_conv 生成子集字体（取组件默认文案+常用汉字的并集），作为生成产物随 ui.c 输出 |
| gen_lvgl.py 槽位常量写死（TOPBAR_H 等） | 改为从 registry 的模板定义读取，模板变更不再需要改生成器 |

### 8.3 不做（Out of Scope，后续版本）

- 屏幕编辑模式（自定义槽位/模板）→ P2
- 组件注册外部化（用户自定义组件）→ P2
- spj 双向同步（导入后再槽位化编辑）→ P3
- 撤销/重做、多工程、云同步 → P3

## 9. 执行计划

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 打通链路**（先行） | 修字体问题；gen_lvgl 常量改读 registry 模板；用 camera-demo.json 走通 生成→编译→WASM 仿真 全流程 | converter 里加载 camera-demo.json 能实时仿真 |
| **P1 槽位画布** | registry.js；拖放吸附交互；属性面板；单屏编辑 | 拖组件能吸附到合法槽位，非法拒绝；改属性画布即时更新 |
| **P2 工程闭环** | 新建/保存/加载工程；页面管理；总览接入；导出 C + 仿真 | 从零搭一个 3 屏工程 → 仿真可手势切屏 → 导出 C 编译通过 |
| **P3 打磨** | 动效细节、空槽位引导提示（新手教学气泡）、错误恢复 | 新手不看文档能完成第一个页面 |
